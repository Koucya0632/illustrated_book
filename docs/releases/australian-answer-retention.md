# 澳洲詞條撤回與舊版手機答案

正式啟用澳洲專屬詞前，必須先在已確認的目標資料庫受控安裝並核實 `installAustralianAnswerRetention` 的兩個觸發器。本批程式部署不會自動安裝它們；安裝前需另完成目標、權限及對現有資料與表鎖影響的檢查。啟用前未建立的保護無法追溯已刪除的卡片或答案；部署後也不涵蓋其他國家的未來新詞。這份說明與本機測試不代表已部署或發布。

撤回時只將詞條設為 `status = 'archived'` 並設定 `deleted_at`，不要刪除詞列、卡列或改變 ID／牌組。現行 `softDeleteWord` 使用這個方式；澳洲租屋分類也必須維持 `australia-housing`，因為免費會員的舊答案透過原分類判斷是否可寫入。公開目錄及新學／複習佇列應繼續按地區守門隱藏撤回內容，`/api/study/answer` 需要保留對既有卡片的寫入能力。恢復公開要走完整批次檢查。

資料庫保護覆蓋 `data/australian-only-word-ids.json` 的全部 19 個預留 ID，從建立草稿起即拒絕硬刪或變更詞 ID、拒絕硬刪或變更所屬卡片 ID、word ID、deck key。六個租屋詞一旦放入 `australia-housing` 便不能搬離；一般詞的現有管理操作不變。這也會拒絕任何以硬刪作回滾的發行／管理工具，連沒有學習紀錄的草稿也一樣；請使用軟撤回，若要修改分類、合併或永久清理，必須先另行設計資料遷移與舊裝置答案處理，不要繞過守門。使用者主動清除自身進度不受此守門影響。擁有資料庫高權限的人仍可停用觸發器、使用 TRUNCATE 或還原舊備份；此守門不能防止這些操作，亦不可把它視為備份。

舊版 iOS／Android 沒有每次作答的穩定唯一識別碼。`sessionId` 屬於整個練習場次，而同一卡在同一場次可能被作答多次；不能以它或請求內容推測去重。首次寫入成功但網路回應遺失時，重送可能重複計入。現行答題路由的卡片排程、熟練度和日誌也不是同一交易，因此中途故障後重試仍有部分成功與重複寫入風險。這份修正只避免撤回時卡片遭刪後的 404 與級聯遺失，**不提供舊版重送冪等性或跨寫入的原子性**。

後續若要真正支援冪等，需新客戶端為每一次作答產生並在本地佇列持久化唯一 ID，所有重試帶同一 ID；伺服器以帳號和 ID 驗證並在同一資料庫交易中鎖定、更新排程、熟練度、日誌及保存可重播回應。不同作答即使卡片和場次相同也必須使用不同 ID。必須涵蓋並行重送、回應遺失、交易回滾、ID 與內容衝突、帳號切換和舊資料解碼。舊版不帶 ID 的請求只能維持原有非冪等行為，不能安全地事後推斷 ID。

本機回歸測試 `tests/australian-answer-retention-postgres.test.ts` 僅允許 localhost 上名為 `tuji_au_test` 的隔離資料庫，建立自己的臨時 schema 並在完成後刪除。它執行實際答題函式、SRS 和資料庫寫入，會員規則直接使用已整合、與發布原型逐位元組一致的實際政策與分類常數，測試帳號會員身分為假資料；仍需整合到發布原型後重跑，以核對最終整合版本、真實帳號及多實例部署。

## 正式開放前的資料庫唯讀阻擋條件

部署完成不等於資料庫保護已安裝：一般 `scripts/migrate.ts` 不會安裝此保護。開放六詞前，必須對確認為 App 正式寫入的主資料庫，使用具唯讀權限的連線，執行 `npx tsx scripts/verify-australian-answer-retention.ts`。設定 `AU_RETENTION_VERIFY_DATABASE_URL` 為該資料庫連線、`AU_RETENTION_EXPECTED_HOST` 和 `AU_RETENTION_EXPECTED_DATABASE` 為獨立核對的目標主機與資料庫名稱；不要把連線字串或密碼寫進文件、日誌或聊天。任一設定缺少、目標不符、無法查證、連到副本或回傳非零退出碼，都視為未通過，禁止開放。

工具在唯讀交易檢查 `public.words`、`public.cards` 上各自的觸發器已啟用、事件與欄位正確、綁定預期函式，且函式內容和程式中全部保留 ID 完全一致。也檢查連線不是讀取副本且該連線使用正常觸發器模式。它不證明 App 部署實際連向同一資料庫、其他帳號不會以特殊複寫模式或高權限操作、或其他觸發器不會干擾；這些需要在正式環境另行核對，並在切換或回復資料庫後重驗。任何跳過、失敗或不確定都不能以部署成功代替。
